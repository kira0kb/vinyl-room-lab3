# Git и сдача работы

## Что уже есть в архиве

В папке проекта сохранён настоящий Git-репозиторий с несколькими коммитами подготовки. Они созданы по мере работы: основа Laravel, модель и CRUD, интерфейс и формы, проверка и инструкции. Это техническая история подготовки проекта; её автор указан как `Project preparation`, а не от твоего имени. Историю можно посмотреть так:

```bash
git status
git log --oneline
```

Папка `.git` скрыта. На Mac сочетание **Command+Shift+.** показывает скрытые файлы в Finder. Не удаляй `.git`, если хочешь сохранить историю.

**Личный удалённый репозиторий не подключён. `push` и `pull` в него ещё не выполнены.** Это отдельный пункт задания: его нужно завершить со своим GitHub/GitLab и учётной записью.

## Подключить личный репозиторий

1. Создай на GitHub пустой репозиторий, например `vinyl-room-lab3`. При создании не добавляй README, `.gitignore` и лицензию: эти файлы уже есть в проекте. Выбери доступ, при котором преподаватель сможет проверить работу.
2. Открой терминал папки проекта. Следующие команды вводи по одной, заменив значения в кавычках своими:

```bash
git config user.name "Твоё имя"
git config user.email "Твой email для Git"
git remote add origin "HTTPS-адрес твоего нового репозитория"
git push -u origin main
```

В строке `git remote add` вместо текста нужен реальный адрес, скопированный кнопкой **Code → HTTPS**. У этого архива `origin` отсутствует, поэтому команда `remote add` подходит для первого подключения. Если ты уже добавила `origin`, проверь `git remote -v` и при необходимости измени адрес через `git remote set-url origin "новый адрес"`.

Если GitHub попросит войти, используй предложенный способ авторизации. Обычный пароль от аккаунта не подходит для HTTPS-операций Git. Не вставляй токены в файлы проекта.

## Выполнить pull с реальным изменением

1. После успешного push открой `README.md` в своём репозитории на сайте GitHub.
2. Добавь в конец одну строку со своей группой, например `Группа: ...`, и сохрани её отдельным коммитом в `main`.
3. В локальном терминале выполни:

```bash
git pull --ff-only origin main
git log --oneline -6
git status
```

Теперь строка с группой должна появиться в локальном README. Это демонстрирует получение настоящего изменения, а не только сообщение `Already up to date`.

Сделай своё осмысленное изменение в коде или описании, проверь его и отправь:

```bash
git add README.md
git commit -m "Уточнить описание лабораторной работы"
git push
```

Команда `commit` создаётся только при наличии сохранённых изменений. Если меняла другой файл, укажи его вместо `README.md`.

## Создать архив для преподавателя

После последнего коммита в папке проекта выполни:

```bash
git archive --format=zip --prefix=vinyl_room_laravel_lab3/ --output=../Vinyl_Room_LR3_submission.zip HEAD
```

Готовый архив появится **на уровень выше папки проекта**. Он содержит только закоммиченные файлы: без `node_modules`, `vendor`, `.env`, рабочей базы и кеша. Пять исходных обложек, миграции, сидер, исходники и собранные JS/CSS включаются.

`git archive` не включает саму историю `.git`. Для подтверждения коммитов, push и pull приложи преподавателю ссылку на свой репозиторий; при необходимости — свои скриншоты терминала. Архив, скачанный из этого ответа, дополнительно содержит `.git`, чтобы сохранить историю подготовки на твоём компьютере.

Перед сдачей проверь `git status`: изменённые нужные файлы должны быть добавлены в последний коммит. Ключ приложения и локальные данные остаются исключёнными из Git.
