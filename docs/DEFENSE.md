# Памятка для защиты

## Что делает проект

«Я перенесла коллекцию музыкальных альбомов из второй лабораторной на Laravel 12. Данные теперь хранятся в SQLite. Можно открыть список и подробную страницу, добавить альбом, изменить его и удалить. При загрузке обложка обрезается до квадрата 900 на 900 пикселей. Для удаления используется Soft Deletes».

## Как проходят данные

Например, при открытии `/albums` Laravel находит маршрут в `routes/web.php`, вызывает `index()` у `AlbumController`, получает записи через модель `Album` и передаёт их шаблону `albums/index.blade.php`. Blade строит HTML, который видит браузер.

Это MVC:

- **Model** — модель `Album`, работа с данными через Eloquent.
- **View** — Blade-шаблоны, внешний вид страниц.
- **Controller** — `AlbumController`, получает запрос, проверяет данные и выбирает действие.

## Семь действий контроллера

| Запрос | Имя маршрута | Метод | Что происходит |
| --- | --- | --- | --- |
| GET `/albums` | `albums.index` | `index` | Показать список |
| GET `/albums/create` | `albums.create` | `create` | Показать пустую форму |
| POST `/albums` | `albums.store` | `store` | Проверить данные и сохранить новый альбом |
| GET `/albums/{album}` | `albums.show` | `show` | Показать подробности |
| GET `/albums/{album}/edit` | `albums.edit` | `edit` | Показать заполненную форму |
| PUT/PATCH `/albums/{album}` | `albums.update` | `update` | Проверить данные и сохранить изменения |
| DELETE `/albums/{album}` | `albums.destroy` | `destroy` | Выполнить мягкое удаление |

В коде всё это создаёт `Route::resource('albums', AlbumController::class)`. `{album}` — идентификатор записи. Laravel автоматически получает объект модели по этому идентификатору. Если записи нет или она удалена, возвращается 404.

## Миграция и модель

Миграция описывает структуру таблицы `albums`. `up()` создаёт её, `down()` удаляет при откате миграции. Название таблицы во множественном числе, модель — в единственном. Поля `release_date`, `cover_path`, `created_at`, `deleted_at` написаны в snake_case.

`$fillable` перечисляет поля, которые можно массово заполнять. Пользовательские данные дополнительно проверяются контроллером.

Мутаторы `title()` и `artist()` убирают крайние пробелы. Мутатор `releaseDate()` записывает дату в формате `Y-m-d`. Cast `date` позволяет после чтения вызвать `format('d.m.Y')`. Cast `array` преобразует JSON с композициями в PHP-массив и обратно. В шаблоне дата выводится как `10.05.2020`, а в БД сохраняется `2020-05-10`.

Сидер `AlbumSeeder` загружает пять начальных записей. После заполнения сайт читает данные из БД, а не из JSON.

## Проверка через Tinker

В отдельном терминале папки проекта выполни:

```bash
php artisan tinker
```

Дальше вводи команды по очереди **внутри Tinker**:

```php
use App\Models\Album;

$album = Album::create(['title' => '  Пробный альбом  ', 'artist' => '  Исполнитель  ', 'genre' => 'Рок', 'release_date' => '2020-05-10', 'description' => 'Альбом для проверки создания через Tinker.', 'cover_path' => 'albums/am.jpg', 'tracks' => []]);

$album->title;
$album->release_date->format('d.m.Y');
Album::find($album->id)->toArray();
```

Ожидаемый результат: название без крайних пробелов, дата `10.05.2020`, новая запись с присвоенным `id`. Обложка берётся из уже существующего файла, поэтому карточка сразу работает. Обнови список в браузере и покажи новый альбом.

Мягкое удаление и восстановление того же объекта:

```php
$id = $album->id;
$album->delete();
Album::find($id);
Album::withTrashed()->find($id)->deleted_at;
Album::withTrashed()->find($id)->restore();
```

`Album::find($id)` после удаления вернёт `null`, а через `withTrashed()` запись видна. `restore()` возвращает её в коллекцию. После демонстрации можно ещё раз выполнить `$album->delete()`. Выход из Tinker — `exit`.

## Что объяснить про формы

При создании и редактировании подключается один `partials/form.blade.php`. При редактировании в поля подставляются значения модели. `old()` возвращает введённые значения, если сервер нашёл ошибку. Файловое поле браузер не заполняет повторно: после ошибки новый файл нужно выбрать заново.

HTML5 проверяет `required`, `minlength`, `maxlength`, `type="date"` и `pattern`. JS включает оформление ошибок Bootstrap. Серверная проверка находится в `validatedData()` контроллера: её нельзя обойти, просто выключив JavaScript.

`@csrf` добавляет защитный токен. `@method('PUT')` и `@method('DELETE')` позволяют передать нужный метод через HTML-форму, которая физически отправляется как POST. `enctype="multipart/form-data"` нужен для передачи файла.

Текст пользователя выводится через `{{ ... }}`: Blade экранирует HTML, поэтому введённый `<script>` отображается текстом.

## Как сохраняется обложка

Контроллер принимает только JPG, PNG и WebP до 2 МБ, не больше 4096 × 4096 пикселей. `CoverImage` с помощью GD вырезает центральный квадрат и сохраняет JPEG 900 × 900. Для каждого загруженного файла создаётся уникальное имя.

Файл лежит в `storage/app/public/albums/uploads`, а в БД — только относительный путь. `public/storage` — ссылка на публичную часть хранилища. При замене обложки прежняя загруженная картинка удаляется после успешного изменения записи. При Soft Deletes обложка остаётся, чтобы альбом можно было восстановить.

## Где адаптивность и сборка

Сетка осталась из ЛР №2: до 576 px одна колонка, от 576 — две, от 992 — три, от 1400 — четыре, от 1500 — пять. Классы `row-cols-*` находятся в `albums/index.blade.php`. Дополнительный breakpoint `xxxl` задаётся до импорта Bootstrap в `resources/scss/app.scss`.

`webpack.mix.js` собирает исходники Bootstrap и собственный SCSS в `public/css/app.css`, а jQuery, JS Bootstrap и собственный JS — в `public/js/app.js`. `mix()` в Blade читает `mix-manifest.json` и добавляет версию файла в адрес, чтобы браузер не показывал старые стили из кеша.
